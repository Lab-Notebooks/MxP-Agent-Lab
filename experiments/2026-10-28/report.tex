{\fontsize{22}{26}\selectfont\bfseries\color{ink} AlphaEvolve on an 8-bit level-set advection kernel}\\[6pt]
{\large\color{muted} Deforming bubble, WENO5 advection, RAPTOR fp8 truncation, and an interface-weighted score.}

\section{Question}
Can the WENO5 advection kernel run in 8-bit (RAPTOR-emulated) while the level set stays within a
tolerable error of an FP64 shadow run, and can AlphaEvolve improve the low-precision seed?

\section{Setup}
App: Deforming Bubble mini-app (Flash-X level set), 64x64, tmax=2, 1 rank. Kernel: \f{advectWeno}
in \f{app/src/advect.cpp}. Raptorize added modes fp64, fp8e4m3, fp8e5m2, lowprec (native float seed),
plus an FP64 shadow run and error columns in \f{history.csv}.

\section{Level-set behavior}
The fp64 run deforms and splits the bubble by t=2. The fp8e4m3 run follows the same topology but
develops ragged contours and spurious phi=0 islands along the thin filament; err\_band rises from
\textasciitilde 1.3e-2 at t=0.5 to \textasciitilde 2.0e-2 at t=2, and wrong-sign cells reach \textasciitilde 16\%.

The optimized seed improves the native float path (err\_band 1.8x lower in the eval run) but does
not change the fp8 path, because RAPTOR truncates the FP64 \f{advectWeno}, not the evolved float
seed. The fp8 animation is bit-identical before and after optimization.

\section{Conclusion}
AlphaEvolve improved the float seed's interface error, but the 8-bit (RAPTOR) path is unchanged.
To affect fp8 output, the optimization target must be the RAPTOR-truncated FP64 function itself.
